# v26.05 — RFDS-008 Evidence Engine and RFDS-019 Hardware Conformance

**Release date:** 2026-08-07
**Archive:** not produced as part of this change — this is a code/documentation
contribution (evidence layer, hardware conformance suite), not a full release-engineering
pass. No new `rf_bk8500b_v26.05.zip`, `PACKAGE_CONTENTS.md` update, or formal review
sign-off is included; those remain a separate step for the project's release owner.
**Python distribution:** `robotframework-bk8500b` 26.5.0

## Changes

- Added `bk8500b/evidence.py`: an RFDS-008 evidence engine recording every public
  keyword call (arguments, duration, result/failure) and every SCPI/legacy-frame
  protocol exchange (hex-encoded raw bytes) to a per-session, timestamped run
  directory under `results/session/rf_bk8500b/`, with a SHA-256 evidence manifest,
  JSONL event/operation/error streams, and redaction of credential-shaped arguments.
- Integrated with the existing `bk8500b.diagnostics.AuditSink`/`MetricsSink` protocols
  (`EvidenceAuditSink`/`EvidenceMetricsSink`) and added `TracingTransport`, a
  transport wrapper capturing raw wire bytes — the true RFDS-019 protocol-boundary
  observation point, since `AuditEvent` alone records transaction outcomes, not the
  literal command/frame bytes.
- Wrapped every `BK8500BLibrary` public keyword with evidence recording via a
  decorator applied uniformly across all 81 `@keyword` methods, independent of
  whether a given method happens to route through the existing `_translate` helper.
- Added `Export Diagnostic Bundle` keyword and its RFDS-017 capability entry;
  regenerated `ai/bk8500b_ai_contract.lock` (81 public keywords).
- Added `tests/hardware/verify_all_keywords.robot`, an RFDS-019 real-hardware
  conformance suite (one test case per public keyword), gated behind explicit
  safety-token-aware flags for any state-changing operation.
- Added `schemas/evidence/*.schema.json`, `docs/logging_and_evidence.md`,
  `guide/EVIDENCE_AND_DIAGNOSTICS.md`, `scripts/validate_evidence.{py,sh,bat,ps1}`,
  and `tests/evidence/test_evidence.py`.

## Compatibility

No existing Robot keyword name, parameter order, default, or instrument-control
implementation changed. The public keyword surface grew from 80 to 81 keywords
(the addition is `Export Diagnostic Bundle`). Existing custom `library._device_factory`
assignments (as used by this project's own fake-transport tests) continue to work
unchanged — they simply do not receive protocol-level tracing, since a fake transport
has no real wire bytes to trace; keyword-level operation recording still applies
regardless of which factory constructed the device.

## Qualification status

Software and fake-transport validation (214 existing tests, unchanged pass status)
remain applicable. The new hardware conformance suite has been dry-run validated
(`robot --dryrun`) but not executed against a physical 8500B in this change, matching
this repository's existing convention of hardware suites requiring `hardware`-tagged
opt-in execution against real bench equipment.
