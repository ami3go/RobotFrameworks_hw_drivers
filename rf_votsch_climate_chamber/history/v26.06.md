# v26.06 Change History

**Date:** 2026-07-31  
**Type:** RFDS-019 conformance execution fix

## Fixed

- The RFDS-019 harness no longer executes the alphabetical keyword inventory against one mutable session without preconditions.
- Every device-facing keyword now receives a connected `default` simulator session before invocation.
- Connection-destructive keywords (`Disconnect`, `Disconnect All`, legacy disconnect, and stop-and-disconnect) are isolated and followed by deterministic recovery.
- Chamber state is prepared for running/stopped, temperature, setpoint, gradient, dryer, and compressed-air assertions.
- Configuration profile keywords receive deterministic profile setup and cleanup.
- Evidence paths now use resolved filesystem paths rather than unresolved Robot variable tokens.
- Legacy `Connect Climate Chamber` now accepts approved `SIM::` resources for protocol-conformance testing while preserving normal IP/hostname behavior.
- Protocol vectors for safe shutdown and disconnect now match the actual serialized SimServ command sequence.

## Evidence improvements

- The harness captures outbound and inbound protocol frames from the transport-boundary trace observer.
- Protocol vectors are compared against observed operations using ordered, placeholder-aware matching.
- Each keyword result includes captured outbound and inbound frames in JSON and CSV evidence.
- A pure-Python Robot-dispatch-equivalent regression executes all 92 exported keywords and fails on cascading `RFDS-CON-002` errors.

## Compatibility

- All 92 public Robot keywords are retained.
- Deprecated v26.03 aliases remain available and continue to emit warnings.
- Physical chamber protocol behavior is unchanged.
- The only driver compatibility change is support for `SIM::` in the deprecated connection keyword during approved simulator testing.
