# Code review — version 26.01

## Result

Approved for initial real-hardware integration testing. Unit-level behavior is
covered; physical relay operation still requires HIL verification.

## Strengths

- Identical boards are addressed by unique serial number, never USB order.
- Partial attachment rolls back already-opened handles.
- Connect/disconnect defaults de-energize all outputs.
- Bulk input is validated before hardware writes.
- All-channel safety operations attempt every channel and aggregate errors.
- Pulse cleanup uses `finally`.
- Dependency injection enables deterministic tests without hardware.

## Residual risks and HIL gates

- DigitalOutput readback proves commanded state, not mechanical contact state.
- USB updates are sequential, not simultaneous.
- Host/application failure cannot guarantee a final de-energized state.
- Exact electrical limits depend on the physical Phidget hardware revision and
  connected relay/load circuit.
- Before production use, verify all eight contact paths with a DMM, unplug each
  USB device during operation, test restart/reconnect, and validate emergency
  isolation and load protection.
