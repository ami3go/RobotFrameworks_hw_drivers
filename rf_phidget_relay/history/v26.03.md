# v26.03 — RFDS-008 evidence engine and RFDS-019 hardware conformance

- Added `rf_phidget_relay/evidence.py`: an RFDS-008 evidence engine recording
  every public keyword call (arguments, duration, result/failure) and every
  underlying Phidget22 SDK call to a per-session, timestamped run directory
  under `results/session/rf_phidget_relay/`, with a SHA-256 evidence manifest,
  JSONL event/operation/error streams, redaction of credential-shaped
  arguments, and correlation IDs linking nested keyword calls.
- Wrapped every public keyword with the new evidence recording (opt out with
  `evidence_enabled=${FALSE}`); added `Export Diagnostic Bundle` to zip a
  session's evidence for troubleshooting.
- Added `tests/hardware/verify_all_keywords.robot`: an RFDS-019 real-hardware
  conformance suite exercising every public keyword against real Phidget
  boards, gated behind `ALLOW_CLOSE`/`ALLOW_CLOSE_ALL` since closing relays
  can connect external circuits.
- Added `schemas/evidence/*.schema.json`, `docs/logging_and_evidence.md`,
  `guide/evidence_and_diagnostics.md`, and `scripts/validate_evidence.{py,sh,bat,ps1}`.
- Added `tests/evidence/test_evidence.py` and `tests/conftest.py`.
- Updated the RFDS-017 AI contract with the new `Export Diagnostic Bundle`
  capability; regenerated its integrity lock.
- Fixed a JSONL sequence-numbering bug (operation/error IDs and stream
  sequence numbers shared one counter, producing gaps) found by the new
  `validate_evidence.py` script's own ordering check while building it.
